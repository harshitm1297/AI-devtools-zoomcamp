# Public task tracker template

Create these issues when publishing the repository:

1. Product specification and architecture — acceptance: reviewed spec and non-goals.
2. Receipt extraction and confirmation — acceptance: supported image completes confirmation safely.
3. Retrieval and deterministic risk rule — acceptance: threshold tests pass.
4. Grounded explanation agent — acceptance: invented citation is rejected.
5. Frontend journey — acceptance: responsive demo works without documentation.
6. Containers and CI — acceptance: clean one-command startup and PR checks.
7. Deployment and rollback — acceptance: public development URL and verified rollback evidence.
8. Observability and alert — acceptance: assessment failure appears across signals and pages responder.
9. Agent extension pack — acceptance: workflow, specialist, MCP server, hook, and permissions demo.

Every issue should contain `Given/When/Then` acceptance criteria. PRs should link the issue, summarize
agent assistance, record manual review, and include commands/output used for verification.
